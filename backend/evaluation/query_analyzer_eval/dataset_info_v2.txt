WHAT THE PARALLEL DESIGN GIVES YOU
----------------------------------
The same scenario in five languages has the same expected labels. Comparing the
analyzer's output across the five versions of one scenario measures whether it
treats languages equally: same intent, same facts extracted, same questions.
Report every metric per language, and report "cross-language agreement": the
share of scenarios where all five versions pass a check.

HOW TO SCORE (one judge call per row)
-------------------------------------
1. confidence      matches expected_confidence (medium vs high is a near-miss)
2. clarification   low confidence <=> expected_needs_clarification
3. extraction      every fact in expected_info_provided is captured (the output
                   may be in any language; judge the meaning)
4. must ask        every must_ask field is in info_needed
5. no re-ask       nothing in info_needed asks for a fact already given or
                   listed in must_not_ask
6. no scope creep  every info_needed item is within acceptable_info_needed
                   (clearly critical extras may be marked "acceptable extra")
Privacy can be checked in plain code first (keyword match on address, phone,
aadhaar, pan, bank, workplace).

The analyzer runs at temperature 0.15: run each row 3 times and take the
majority. That is 600 calls per full run on the Hugging Face credit pool.

LIMITS
------
- Tamil and Kannada text was written by an AI assistant and has not been
  checked by a native speaker. Hindi and Hinglish should be read for naturalness.
- Labels are judgement calls and need review, ideally by someone with
  family-law experience.
- "Real-world" here means modelled on real forum posts and on the project's
  own test conversations, not on conversations from outside users.
- Only 2 rows expect "medium" confidence, so that level is barely tested.
