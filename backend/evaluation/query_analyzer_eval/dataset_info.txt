Purpose:   Evaluate the FIRST call of QueryAnalyzer.analyze_query()
           (nodes/query_analyzer.py), i.e. the analyze_query node, on a fresh
           user message. It must: identify the intent, set a confidence level,
           extract the facts the user already gave, and list only the
           critical facts still missing.

           The revalidate node reuses the same class on a different kind of
           input; that is covered separately in revalidate_eval/.

HOW TO SCORE
------------
Use an LLM judge per row, with these checks (each pass/fail):
  1. confidence     - matches expected_confidence (medium vs high may be
                      treated as a near-miss rather than a fail)
  2. clarification  - needs_clarification behaviour matches
  3. extraction     - every fact in expected_info_provided is captured
                      (semantic match, key names can differ)
  4. must_ask       - every must_ask field is present in info_needed
  5. no re-ask      - no info_needed item asks for something already
                      provided or listed in must_not_ask
  6. no scope creep - info_needed items are within acceptable_info_needed
                      (judge semantically; extra items that are clearly
                      legally relevant can be marked "acceptable extra")
Report pass rates per check and per category. Checks 5 and 6 are the most
important: they map directly to the "keeps asking irrelevant / repeated
questions" problem seen in manual testing.

KNOWN LIMITATIONS
-----------------
- Written by an AI assistant; the acceptable_info_needed lists are judgement
  calls and should be reviewed, ideally by someone with family-law
  experience.
- 42 rows give directional signal per category (2-6 rows each), not tight
  statistics.
- The analyzer runs at temperature 0.15, so some variance between runs is
  expected. Run each row 2-3 times and report the majority result.
